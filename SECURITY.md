# Security

Newbie Cloud is a single-user, self-hosted control plane. It stores encrypted cloud credentials and can modify DNS when explicitly enabled.

- Use the random administrator token generated by setup and keep the encryption key outside source control.
- Production sessions use HttpOnly, Secure, SameSite=Strict cookies; browser writes require a matching Origin. Bearer access is intended for trusted local tooling.
- Cloud credentials use AES-256-GCM with random IVs and account/provider-bound associated data. API responses and audit logs never return stored credential values.
- DNS writes require a persisted, expiring plan. Read-only mode, protected-record confirmation, account settings, and current record state are rechecked before execution.
- An operation is claimed atomically before provider writes. Timeouts require human review, not automatic replay. This does not turn external cloud APIs into an atomic transaction and cannot eliminate changes made by other consoles between verification and write.
- Sign out clears the current browser cookie. Rotate ADMIN_TOKEN to revoke all previously issued sessions. Preserve ENCRYPTION_KEY until all credentials are migrated or removed.
- Report vulnerabilities through GitHub private vulnerability reporting when enabled, or create a minimal issue without secrets. Do not attach tokens, private keys, full request headers, or database dumps.
- Docker deployment uses local SQLite with encrypted cloud credentials. Preserve the data volume and its encryption key together. The default image runs as a non-root user; the default Compose service has no Docker socket.
- Opting into a Docker socket gives the application host-level daemon authority. Application read-only mode and a read-only bind mount are not OS-level isolation from that authority. Keep the socket local; the HTTP API only exposes authenticated, validated reads and explicitly enabled start/stop/restart operations.
- Container actions recheck the full container ID, name and state, and protect the control plane itself. No arbitrary Docker API proxy, exec, creation or deletion endpoint is provided. Container logs are transient responses and may contain the target application's own secrets; stored inspect environment variables are not returned.
- Node deployment validates Host and uses an explicitly configured PUBLIC_ORIGIN behind HTTPS proxies. It does not trust arbitrary forwarded-origin headers. `/api/` responses remain no-store and are excluded from PWA caching in both deployment modes.

This initial MVP is not an audited security product. Keep tokens scoped to the resources and capabilities you actually use, and run only within your own account.

Static publishing creates a new, randomly named Cloudflare Pages project and never modifies pre-existing sites or DNS. It accepts validated static build output, verifies file hashes, and does not create Functions or paid resources. File filters cannot detect secrets intentionally embedded in otherwise valid JavaScript/JSON. Publish only content intended to be public.

Project Agent tokens are random, hashed at rest, expiring and revocable. They only access their assigned project, cannot expose cloud credentials, and require separate rollback permission. Revocation blocks new requests, not a cloud operation already accepted. Production writes are claimed before submission; uncertain results are reconciled without automatic replays. Cloud-side operations and local DB updates cannot form a distributed atomic transaction.

Third-party plugins use a dedicated resource protocol. Previewing reads manifests and pins sources without executing package scripts. Declarative plugins use declared public HTTPS hosts and independent encrypted configuration; they do not receive existing cloud-account credentials. Resource responses are transient and excluded from PWA caching.

JavaScript plugins require `ALLOW_CODE_PLUGINS=true` on Node/Docker plus explicit installation consent. A fresh child process, minimal environment, filesystem permissions and time/output limits reduce accidents; they are **not a sandbox for malicious code**. Trusted code can still exercise the runtime user's network/system capabilities, including reachable Docker sockets. Never enable this option for untrusted code. See [plugin documentation](docs/plugins.md).
